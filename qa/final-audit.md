## Verdict

**Changes required before release: 0 Critical, 1 Important, 1 Minor finding.** The implemented accounting and historical snapshot model match the approved direction; one reproducible cross-feature status defect contradicts the next Save action's Google behavior. Fix Important F1, rebuild the standalone/ZIP/worker, and perform focused re-review alongside the independent final QA gate. F2 is a nonblocking wording correction.

## Findings

### F1 — Important: canceling an edit leaves a false no-Google promise beside the next new receipt's Save action

- **Location:** `app.js:424–428` (`updateEditUI`), `app.js:446–455` (restore/cancel), `app.js:327–338` (reset), with actual send path at `app.js:819–825` and visible status next to Save at `index.html:133–135`.
- **Cause:** entering edit writes “Изменения сохранятся только в этом браузере, без повторной отправки в Google Forms.” Leaving edit updates the banner and button but has no corresponding branch to reset the status. Restoring the previous draft therefore presents `Сохранить чек` underneath the stale future-tense local-only promise. Google remains enabled by the preserved default.
- **Reproducer:** save any synthetic receipt with default Google setting; enter a next-client draft; open and edit the prior receipt; cancel the edit; inspect the restored new calculation and save it. The button reads `Сохранить чек`, its status still promises no Google resend, and the new receipt invokes the Google submission path.
- **Fresh evidence:** both the existing VM harness (loaded without running its suite) and actual Chromium with the supplied normal runtime reproduced the same status. Browser result: `button="Сохранить чек"`, `status="Изменения сохранятся только в этом браузере, без повторной отправки в Google Forms."`, `newReceiptMockSubmissions=1`, `externalRequests=0`. Google submission was replaced with a counter and every external request was blocked. No actual data was sent.
- **Consequence:** the app gives incorrect transmission guidance immediately before saving a different client's new receipt. This violates the spec's distinct/honest local and Google labels even though the edit itself correctly never sends.
- **Remedy:** render a context-aware prospective Save status whenever edit mode exits, the previous draft is restored, a new calculation begins, and the Google preference changes. Keep completed-operation success messages distinct from promises about the next Save. Cover cancel with populated/default prior draft and successful edit-return; assert the new receipt disclosure matches the effective Google setting, and edits remain local-only. Do not change the authorized Google default merely to hide the defect.

### F2 — Minor: worker-update confirmation still claims a draft will be discarded

- **Location:** `app.js:853–857`, especially `app.js:855`.
- **Evidence:** the confirmation states “Незавершённый расчёт будет сброшен.” New draft input/pagehide persistence and startup recovery (`app.js:260–316`, `app.js:998–1005`) instead preserve and restore the unfinished calculation. The assembly report explicitly confirms the revised broad browser test expects the retained draft, rather than default values, after reload.
- **Consequence:** an alarming, obsolete claim discourages updating and contradicts the new draft behavior. This is a baseline string made stale by the new lifecycle, not a claimed data-loss bug.
- **Remedy:** explain that the application reloads and locally saved history/draft remain; if a draft write fails, use the existing honest draft warning rather than promising guaranteed recovery. Retain the deliberate update confirmation.

## Checks and evidence without additional findings

- **Accounting:** `core.js:14–39` computes charged amounts in integer kopecks. Actual revenue replaces total and recomputes tax/fee (`32–34`); expenses include rent, consumables, material costs, extras and deductions (`36`), and personal income is total minus those expenses (`37`). Salary is not deducted again. The app keeps original quote/difference, pins manual price, allows negative income with a visible warning, and rejects a non-positive total (`app.js:740–776`). Templates/repeat strip actual price (`app.js:134`, `133`, `951`). No new accounting defect identified.
- **Historical authority:** edit uses original rates (`app.js:699`) and original material name/unit/unit price (`68–70`, `410–422`), including the full historical catalog authority when a quantity goes to zero (`771–776`). Unsupported legacy snapshots make edit unavailable, while view/repeat remain explicit (`923`, `942–952`). Receipt ID/date and creation metadata are preserved (`466–469`), previous versions are flattened/deep-cloned (`457`), and edits/undo do not enter the Google path (`812`, `463–489`).
- **Revision integrity/concurrency:** edit and undo compare the full current receipt token before their single history write (`458–487`); a known intervening same-receipt change is rejected. This is optimistic checking, not transactional cross-tab compare-and-swap. Truly simultaneous whole-history writes retain localStorage's architectural limitation; the progress ledger explicitly records that boundary. This audit does not claim serialized concurrent writers. Failed draft restoration after a successful edit retains recovery metadata (`281`, `468`, `473`).
- **Draft lifecycle:** raw strings and bad-input markers are distinct from validated receipt values (`222–258`, `504–512`); untouched defaults do not persist (`238–265`); committed sourceDraftId avoids old-client resurrection after failed draft removal (`279–281`); unknown/missing-material drafts retain their source and warn (`283–315`). Programmatic name selection/contact/repeat/template/material/time/reset paths integrate persistence. Edit cancel retains the prior draft composition; the discovered defect is its displayed transmission status.
- **Stable palette/duration:** favorites/order affect presentation and do not remove charged active quantities (`89–95`, `360–370`, `731–738`). Name-only history selection does not load a recipe (`910–913`). Exact canonical hours survive optional presentation, with fallback for inexact fractional minutes (`152–189`), and manual rent entry unlinks. Replace-current guards apply to repeat/template (`323–325`, `133`, `948`). No silent material substitution/drop identified in the reviewed paths.
- **Backups and validation:** old schema 2/3 imports are accepted with preview/cancel and pre-import source snapshot (`552–590`); current ID conflicts retain the current receipt explicitly. Revision arrays are exported with the receipt and validated flat (`401–411`, `543–546`). New input identifiers used in inline handlers are constrained, user strings are escaped (`41–49`, `243–258`, `382–411`, `618–620`), and client sharing excludes internal income/cost (`929–939`). No new executable-string injection path identified. This is not a claim that permissive legacy optional metadata has a comprehensive accounting consistency validator.
- **Default quick-entry UI:** inspected baseline `qa/calc-320.png`, nondefault `qa/task4-mobile.png`, and fresh `qa/final-default-320.png` under this session. The fresh default hides backup/draft/edit notices, suggestions, and manual-price controls, keeping only their compact optional affordances. The client explanation and time options add scroll distance before the materials grid; this is a visible density tradeoff, not evidence of a broken flow. Seven material positions remain stable, details remain collapsed, and no mandatory client/backup modal was introduced. Full-page screenshot fixed overlays are captured at the viewport's position and do not prove Save is permanently covered. CSS reserves 205px bottom space and hides the summary during calculation-input focus (`styles.css:135`); actual narrow-layout/Save reachability checks belong to the parallel independent QA gate.
- **Standalone/ZIP/worker:** independently reconstructed the inlined HTML from canonical source without writing it: exact equality PASS. Recomputed app-shell digest `71ac63db0377` matches `sw.js`. ZIP CRC PASS and all **21 entries** byte-for-byte match their source. The identified app defect is therefore also present in the assembled deliverables. Worker fetch scope is limited to app-shell URLs and same-origin GETs; cache deletion uses the palette-specific prefix (`sw.js:2–36`). Standalone bypasses worker registration (`app.js:843`). No original master-calc storage/cache migration introduced.
