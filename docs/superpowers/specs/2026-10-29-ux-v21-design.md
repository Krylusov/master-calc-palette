# Master Calc Palette v2.1 — approved direction from UX discussion

Goal: preserve the quick client calculation workflow while implementing the four stages in the UX review. User requested division among implementers/reviewers, final assembly audit and independent testing. This is execution authorization for the discussed staged work; no additional product scope.

## Global Constraints
- Static vanilla HTML/CSS/JS PWA; offline/local HTML support; no external runtime dependencies.
- Preserve existing palette storage keys and never touch original master-calc storage/caches.
- Preserve historic receipts, rates, exact durations, existing backup versions and hourly rent model.
- Master works for self: income = actual revenue minus direct costs and deductions.
- Stable material positions; no automatic sorting, automatic recipe loading, mandatory client profiles or blocking backup reminders.
- UI Russian; accessible labels; narrow 320px phone layout; no horizontal page overflow.
- Tests never send actual data to Google Forms; mock/abort external requests.
- Existing public site remains intact until all review/test gates close; build a reviewable standalone HTML and ZIP.

## Design
1. One persistent draft captures raw form input (including blanks/intermediate invalid fields), client, extras, selected materials and context. Explicit restored banner and New calculation; reset only after successful receipt write. Flush on input/pagehide, avoid old client resurrection. Existing draft errors preserve source and show honest warning. A draft is not a saved receipt. Do not persist default untouched form.
2. Material favorites/order editable in Settings only with accessible up/down and pin controls. Stable default seven. Active quantities remain visible/charged when unpinned or archived. No drag-to-reorder during calculation. Keep old field IDs and precision for compatibility.
3. Duration UX offers optional hours/minutes presentation without losing exact legacy hours. No automatic rounding or forced link. Optional explicit Rent equals work; manual rent input unlinks. Keep decimal-hours fallback if exact fractional minutes cannot display faithfully. Compact summary always shows client price, income, material subtotal; expandable detail; keyboard-safe bottom total. Rename tabs to История and Настройки.
4. Client suggestions derive from local history; selection only changes name. Receipt view separate from repeat (new calculation at current rates). No identity merging by name; show dated visit choices. Explicit replace-current-draft guard when loading recipe/template into populated form.
5. Edit receipt uses ORIGINAL saved rates and material names/units/unit prices, preserves ID/date; no Google send on edit. Clear edit banner and Save changes, cancel restores prior draft. Append immutable previous version for undo; undo requires current revision match. Missing rate snapshots in legacy receipts: view/repeat allowed, edit explicitly unavailable (never fabricate original rates). Concurrent modification check before edit/undo. Backups retain revisions.
6. Optional actual client price (kopecks), default follows calculated quote; manual price stays pinned on composition change with visible warning/difference. Tax/fee recomputed from actual revenue; direct costs preserved; income = actual revenue minus direct costs minus deductions. Quote remains visible and reset action available. Templates/repeat must not silently inherit a manual discount. Negative income allowed with visible indication, not blocked; non-positive receipt total disallowed.
7. Backup: last export timestamp and concise nonblocking reminder based on newly changed receipts, import preview with count/config changes, distinct local/cloud labels. Optional Google send setting, preserve prior default behavior for existing users; label honestly as unconfirmed. No auto resend of corrected receipts. Sharing client summary omits income/cost (copy text, no automatic transmission).

## Approaches
- Full CRM/cloud rewrite rejected: exceeds quick local calculator scope.
- UI-only restyle rejected: fails draft and historical editing reliability.
- Chosen execution direction: incremental local enhancements, sequential implementers on shared files and independent gates.
